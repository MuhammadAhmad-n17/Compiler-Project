# ⚔️ C++ Bankai Mode Lexical Analyzer (Compiler Construction - Phase 1)

## 🎯 Project Overview
This project implements a Lexical Analyzer (Scanner) for a custom, Mini C++-like language, "C++ Bankai Mode," using the Flex tool. This is Phase 1 of the compiler construction process.

The scanner successfully recognizes, classifies, and reports all tokens from a unique sample program (`test_bankai.txt`), adhering to the required output format:
```
Line <n>: <TOKEN TYPE> <lexeme>
```

## ✨ Uniqueness & Language Design
The language is themed around the Japanese anime *Bleach*, where keywords are given a "final form" by adding the suffix `_bankai`. This meets the Uniqueness Requirement for the assignment.

### Token Set (15+ Keywords, Operators, and Punctuations)
| Category | Token Examples | Description |
|----------|----------------|-------------|
| Keywords (15) | int_bankai, void_bankai, if_bankai, for_bankai, return_bankai | Defines fundamental control flow and types. |
| Custom Operators (5) | add+, sub-, mul*, div/, rem% | Custom arithmetic operators (e.g., `i add+ 1`). |
| Custom Punctuations (2) | {b, } | Custom opening and closing braces for code blocks. |
| Custom Comment | #...# | Single-line comment format. |

## Example Program (`test_bankai.txt`)
The program is a unique, 38-line sample demonstrating variable declaration, custom operators, conditional statements, and loops (`for_bankai`, `while_bankai`).

## ▶️ How to Compile and Run (WSL/Linux)
The scanner must be compiled using Flex and GCC in a Unix-like environment.

### 1. Compilation Sequence
Execute these commands sequentially in your project directory:
```bash
# 1. Generate the C source file (lex.yy.c) from the Flex file.
flex scanner.l

# 2. Compile the C code into the runnable executable 'lexer',
#    linking the Flex library (-lfl).
gcc lex.yy.c -o lexer -lfl
```

### 2. Running the Analysis
The compiled scanner (`./lexer`) runs on the test program and automatically creates/updates the output files (`tokens.txt` and `error_file.txt`) as defined in the main function of `scanner.l`.
```bash
# Execute the scanner on the sample program
./lexer test_bankai.txt
```

### 3. Reviewing the Output
```bash
# View the final token stream
cat tokens.txt

# View the lexical errors (e.g., Unrecognized Symbol @)
cat error_file.txt
```

## 🐞 Error Handling
As required, the scanner includes robust error handling to report invalid tokens with their line numbers.

**Error Source:** Line 37 of `test_bankai.txt` contains the intentional error: `@`.

**Error Log Output:**
```
Line 37: ERROR Unrecognized Symbol @
```
(Refer to `error_file.txt` for the full error log.)

This demonstrates the scanner correctly invoking the `yyerror` function for any unmatched character, fulfilling the error handling requirement.
